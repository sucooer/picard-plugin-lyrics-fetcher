# Lyrics Fetcher

为 MusicBrainz Picard 3 抓取歌词的插件，支持 **网易云音乐**、**酷狗音乐** 和 **LRCLIB** 三个来源。

## 功能

- 从**网易云音乐**、**酷狗音乐** 和 **LRCLIB** 抓取歌词，写入音频标签
- MP3 写入 `syncedlyrics`（带时间轴）；FLAC/OGG/M4A 存不了，就把带时间轴的 LRC
  写进 `lyrics` 标签
- 清理歌词：去掉开头的制作人员信息（`作词 : XXX`）和只有时间轴的空行
  （`[00:02.552]`）
- 可选：网易云追加中文翻译，生成**双语歌词**
- 可选：导出 `.lrc` 边车文件（默认**不导出**）
- 可选：已有歌词时不覆盖
- 来源**可勾选任意组合**，默认三个全开，按 网易云 → 酷狗 → LRCLIB 的顺序依次尝试

## 选项（一共 6 项）

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| 歌词来源 | 三个都勾选 | **勾选**要用的源，按 网易云 → 酷狗 → LRCLIB 顺序依次尝试；全不勾则不抓取 |
| 把歌词写入音频标签 | ✅ | 关掉就完全不抓取 |
| 清理歌词 | ✅ | 去掉制作人员信息和空行 |
| 网易云：追加中文翻译 | ☐ | 双语歌词 |
| 已有歌词时不覆盖 | ✅ | |
| 导出 .lrc 文件 | **不导出** | 可选「仅当标签存不了时间轴时」或「总是」 |

## 安装

在 Picard 里打开 **选项 → 插件 → Install Plugin…**，选择 **本地仓库** 页签，
把本目录的路径填进去即可。

命令行方式：

```bash
picard-cli plugins install /path/to/picard-plugin-lrclib-lyrics
```

## 使用

安装后插件会出现在 **选项 → 插件** 列表里，自动启用，并在左侧选项树
「插件」节点下多出一个 **歌词抓取** 设置页（英文界面下为
**Lyrics Fetcher**）。插件列表里的**插件名**也跟着界面语言走，中文界面下显示
**歌词抓取**。

流程是全自动的：把音乐拖进 Picard → 插件按「标题 + 艺人 + 专辑 + 时长」查询
→ 结果写进元数据面板 → **点保存才会写进文件**。

### 手动触发（右键菜单）

自动抓取不灵、或者想单独给几首歌补歌词时，选中曲目或专辑 →
**右键 → `抓取歌词（网易云 / 酷狗 / LRCLIB）`**。

菜单名跟随 Picard 的界面语言：英文界面下显示
`Fetch lyrics (NetEase / Kugou / LRCLIB)`。

手动触发会**忽略「已有歌词时不覆盖」**（你都主动点了），其余设置照常生效。
它也会处理没匹配到 MusicBrainz 的曲目——只要文件本身有标题和艺人标签就行。

### 排查：为什么没抓到歌词

打开 **帮助 → 查看日志**，搜 `Lyrics`：

| 日志内容 | 含义 |
| --- | --- |
| `Lyrics Fetcher: enabled` | 插件加载成功（没有这行 = 插件没装好或没启用） |
| `automatic lookup hook is active` | 自动抓取的钩子被触发了（每次启动只打一次） |
| `already has lyrics and "never replace" is enabled` | 文件已有歌词，被「不覆盖」挡住了 |
| `has no title and/or artist tag` | 文件缺少标题或艺人标签，无法查询 |
| `NetEase returned no results` / `Kugou returned no results` / `no LRCLIB entry` | 对应来源没收录 |
| `— NetEase "..." by ...` / `— Kugou "..."` | **成功**，后面是选中的记录（含时长和专辑名） |

如果连 `automatic lookup hook is active` 都没有，说明钩子没被触发，直接用右键菜单。

## 三个来源的取舍

| | 网易云音乐 | 酷狗音乐 | LRCLIB |
| --- | --- | --- | --- |
| 中文歌 | **很强** | 强 | 一般 |
| 日文歌 / 动漫 OST | **很强** | 强 | 一般 |
| 欧美歌 | 强 | 一般 | 强 |
| 版权下架的曲目 | 查不到（例如周杰伦原版） | 可能有 | 可能有 |
| 额外福利 | 中文翻译、罗马音 | 无 | 无 |
| 接口稳定性 | 非公开网页接口，可能失效 | 非公开网页接口，可能失效 | 公开 API，稳定 |

来源在选项页是**三个勾选框**，可以任意组合。尝试顺序固定为
**网易云 → 酷狗 → LRCLIB**，任一处命中就停，不会继续往下查。

实测 Mrs. GREEN APPLE《POPS》(2026) 整张 16 首：网易云覆盖 14 首，酷狗单独
覆盖 10 首，而**网易云 + 酷狗合起来 16/16**——酷狗正好补上网易云缺的两首。
LRCLIB 在这张专辑上只有 10 首。

### 网易云为什么走 HTTP/1.1

Picard 的网络层默认协商 **HTTP/2**，而 `music.163.com` 的 CDN 会**掐断 Qt 的 HTTP/2
连接**。用 Qt 6.11 实测：

```
搜索 HTTP/2 开启   #1  RemoteHostClosedError（卡 5.29 秒后失败）
搜索 HTTP/2 开启   #2  OK
搜索 HTTP/2 开启   #3  OK
搜索 HTTP/1.1      #1  OK  0.52s
搜索 HTTP/1.1      #2  OK  0.60s
搜索 HTTP/1.1      #3  OK  0.50s
```

HTTP/1.1 不仅 3/3 成功，还快十倍。所以插件为网易云单独建了一个
`QNetworkAccessManager`，关掉 `Http2AllowedAttribute`（仍遵循系统的代理设置）。
LRCLIB 继续走 Picard 自带的 web service。

### 酷狗接口的两个坑

酷狗走 Picard 自带的 web service（不像网易云那样需要自建 HTTP/1.1 客户端），
但有两个地方要注意：

1. **歌词接口三个参数缺一不可**：
   `?keyword=<歌名>&hash=<hash>&timelength=<毫秒>`
   - 只给 `hash` → 返回空 body
   - 只给 `keyword` + `hash` → **HTTP 500**
   - `timelength` 是**毫秒**
2. **两个接口都返回 `Content-Type: text/html`**（不是 `application/json`），
   所以插件请求时不带解析器，自己解码 body。

另外酷狗歌词的**第一行是 `[00:00.xx]歌名 - 艺人`**（标题行），插件会连它
一起清掉；随后几行是 `词：`/`曲：`/`制作人：`，也在清理范围内。


## 匹配策略

三个来源都不用 MusicBrainz ID，插件按下面的规则自己挑记录：

1. **标题**归一化后（忽略大小写和多余空格）必须一致；**仅当专辑名也对得上时**，
   才允许来源标题多一个括号后缀，例如本地 `怪物` 配 `怪物 (…LIVE 2024)`，
   且后缀内容必须出现在专辑名里。后缀对不上专辑的一律拒绝
2. **艺人**必须一致，或者一方包含另一方（应对 `藍井エイル` 与 `藍井エイル & ASCA`）
3. **专辑**不能矛盾：完全一致最优，一方包含另一方次之（`THE BOOK 2` 对
   `THE BOOK 2 EP`），明确冲突则直接拒绝——这是防止 Live 专辑被配上录音室
   歌词的关键
4. **时长**误差不得超过 **5 秒**。专辑版、单曲版、Live 版之间的差距远大于此，
   所以超出就判定是另一个版本，直接拒绝
5. 丢掉没有任何歌词的记录
6. 排序依次比较：专辑匹配程度 → 标题是否完全一致 → 翻唱/伴奏惩罚 → 时长差
7. 网易云和酷狗额外给翻唱/伴奏类标题降权

来源缺少专辑名或时长时**不拒绝**，只是排在后面：宁可给出歌词，也不因为对方
没填元数据就放弃。

任何一条规则都不满足时，插件会**换下一个来源**；所有来源都失败就什么都不写，
也不会报错。

实测 YOASOBI《YOASOBI 5th ANNIVERSARY DOME LIVE 2024 “超現実” at TOKYO DOME》
整张 27 首：旧规则在 23 首上抓到了歌词，但**全部是录音室版本**（`怪物` 拿到
206 秒的录音室版，而不是 284 秒的现场版）；新规则 27 首全部命中同名 Live 条目。

关于接口选择：LRCLIB 用的是 `/api/search` 而不是 `/api/get`。后者要求标题、
艺人、专辑、时长全部精确一致，任何一项对不上就返回 **404**，Picard 会把它当成
网络错误写进日志。搜索接口始终返回 200（没找到就是空列表），并且结果里直接带
歌词正文，不用二次请求。

关于重试：Picard 的 web service 只会自动重试 429 / 503 / ServiceUnavailable，
**协议层错误（HTTP/2 stream error、连接中断）会直接丢给插件**。这类错误通常是
偶发的，所以插件会自己重试 **2 次**再放弃；某个来源失败后自动换下一个来源。
日志里能看到 `retrying (attempt 2 of 3)`。

「搜索返回空」不算错误，不会触发重试——那说明对方确实没收录。

## 注意事项

- **收录率不是 100%**。冷门曲目、专辑独占曲经常两个来源都查不到。
- **繁简字形和艺人写法会影响匹配**。同一首歌可能只收录了繁体版。
- **Live 专辑需要来源也收录了现场版**。插件不会把录音室歌词配给现场录音，
  所以来源只有录音室版本时，宁可抓不到也不写错。
- **歌词质量参差**。可能混入罗马音、翻译或元信息行。保存前扫一眼。
- 抓不到时，先把文件里的 title / artist 改成更常见的写法再重试。
- **界面语言跟随 Picard**。插件自带 `locale/` 翻译（中文和英文），右键菜单名和
  选项页标题都会跟着 Picard 的界面语言切换；`MANIFEST.toml` 里的
  `[name_i18n]` / `[description_i18n]` / `[long_description_i18n]` 让**插件列表里的
  插件名和说明**也跟着切换。插件作者请勿把界面文字写死成中文：英文来自
  `locale/en.toml`，其他语言没有自己的翻译文件时也回退到它；如果 `locale/` 整个
  丢失，菜单会显示成翻译键（如 `action.fetch_lyrics`）。
- **版本号写在 `MANIFEST.toml` 里**。`version` 字段和 git 标签 `vX.Y.Z` 一起构成
  版本链，Picard 的「刷新全部」靠它判断有没有新版本。
- 网易云走的是它播放器自己调用的公开网页接口（`music.163.com/api/...`），
  **不是官方文档化的 API**，随时可能变更或拒绝请求。仅供个人整理本地音乐使用。

想看具体发生了什么，打开 **帮助 → 查看日志**，搜 `Lyrics:`：成功会记录选中了
哪条记录（含时长和专辑名），失败会记录原因。

## 格式支持（重要）

**只有 MP3 能存带时间轴的歌词。** 这是 Picard 的限制，不是插件的问题：

| 格式 | `syncedlyrics` 标签 | `lyrics` 标签内容 |
| --- | --- | --- |
| **MP3** (ID3) | ✅ 支持 | 纯文本 |
| **FLAC / OGG / Opus** (Vorbis) | ❌ **Picard 会丢弃** | **带时间轴的 LRC** |
| **MP4 / M4A** | ❌ **Picard 会丢弃** | **带时间轴的 LRC** |

原因：Picard 在 `picard/formats/vorbis.py` 和 `mp4.py` 里把 `syncedlyrics` 放进了
`UNSUPPORTED_TAGS`，保存时由 `File._tags_to_update()` 过滤掉——**标签会被静默丢弃，
文件甚至不会被标记为"已修改"**。只有 `id3.py` 的 `UNSUPPORTED_TAGS` 里没有它。

**FLAC 等格式没有专门的"同步歌词"字段**，所以插件把带时间轴的 LRC 直接写进
`lyrics` 标签——**时间轴就在标签里，不需要额外文件**。

如果某个播放器不解析标签里的 LRC（会把 `[00:23.846]` 当普通文字显示），把
「导出 .lrc 文件」改成「仅当标签存不了时间轴时」或「总是」，插件就会额外生成
同名 `.lrc` 文件。**默认不生成。**
